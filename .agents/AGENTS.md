## Project overview
AI-agnostic engineering toolkit: reusable agent skills, and a self-updating memory
file (refreshed by a `pre-commit` hook).

## Skills
Skills live in `.agents/skills/<name>/SKILL.md` (YAML frontmatter + Markdown).
If your tool does not auto-load skills, open the matching `SKILL.md` and follow it.
- `task-breakdown`: first asks the user for the document/request to break down, then plans it into `Tasks/` and executes it.
- `pytest-unittest`: write pytest unit tests.
- `bilingual-commit`: read the staged diff and write the commit message in English and Spanish for non-technical readers.

## Working rules for agents
1. For multi-step work, use the `task-breakdown` skill. For any Python behaviour change, add tests with `pytest-unittest`.
2. Write every commit with the `bilingual-commit` skill: Conventional Commit subject (`feat:`, `fix:`,
   `test:`, `docs:`, `refactor:`, `chore:`) plus a plain-language body in English and Spanish.
   **Never add an agent signature** (`Co-Authored-By:` an AI, "Generated with ...").
3. Run `python -m pytest -q` before committing. Don't commit failing tests.
4. Scripts are stdlib-only Python 3.10+. Don't add runtime dependencies to hooks.
5. Any AI integration goes through `scripts/ai_runner.py` (`AI_CLI` env var) and must
   degrade gracefully when no AI is configured.
6. Record durable lessons below under *Decisions & learnings*.

## Decisions & learnings
- 2026-10-28: The memory hook is `pre-commit`, not `post-commit`, so the refreshed
  AGENTS.md lands in the *same* commit with no amend.

  workflow, `post-commit`, `docs/features/`) and the skill evals. Only the memory hook remains.

  with no AI/agent signature. This is a skill (`bilingual-commit`), not a hook.
- 2026-10-28: `ticket-api/` is a self-contained Django + DRF project (ABAI technical test) with its own
  `.venv`, `requirements*.txt` and `pytest.ini`. Run its tests from inside `ticket-api/`; the root
  pytest config (`testpaths=["tests"]`) does not collect them.
- 2026-10-28: Task plans live in `Tasks/` (one file per feature plus `Tasks/README.md` as the index),
  not in a single `TASKS.md`.
- 2026-10-28: There is one README, at the repo root, with an "Agent toolkit" section and a "Ticket API"
  section (paths relative to `ticket-api/`). Don't add `ticket-api/README.md` back.
- 2026-10-28: Outside this repo the pyenv `python3` shim can fall back to the system Python 3.9. Use an explicit
  `python3.11`/`python3.12` when creating venvs elsewhere.
- 2026-10-28: `.agents/AGENTS.md` is the single memory file. The root `AGENT.md`, `AGENTS.md`, `CLAUDE.md`
  and `GEMINI.md` were removed; root `AGENTS.md` and `.claude/CLAUDE.md` are symlinks to it. Gemini CLI
